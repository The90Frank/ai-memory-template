# Response style

Answers **always concise and schematic**. Never long messages.

**Why:** explicit request in the first session (2026-08-29). Information density is preferred over extended explanation.

**How to apply it:**

- bullets, tables, directory trees, Mermaid diagrams instead of paragraphs
- one reasoned recommendation, not a survey of alternatives
- no preambles, no summaries of what is about to be done
- technical documentation in Markdown, diagrams in Mermaid — this applies to produced files too, not only to the chat
